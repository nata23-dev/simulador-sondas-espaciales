## Metodología de validación

1. **Autorizar una etapa y fijar alcance.** Inspeccionar `git status`, fuente y evidencia; preservar cambios locales. Codex o Claude implementan únicamente esa etapa.
2. **Comprobar localmente.** Ejecutar pruebas específicas y, si cambia lógica, la batería `node --test tests/*.test.mjs`; `npm run build`; `git diff --check`. Si cambia interfaz, usar navegador real y registrar dimensiones, estado DOM/cámara y manifiesto además de capturas. Si cambia ciencia, contrastar contra una referencia independiente; una regresión sobre el mismo archivo no basta.
3. **Auditoría por Gemini o Claude.** Separar su dictamen de las pruebas del implementador; si el auditor implementó la etapa, declararlo y no aprobar por sí solo cambios de física o datos. Revisar hallazgos reproducibles y la procedencia de las evidencias.
4. **Corrección acotada y nueva comprobación.** Documentar cada defecto y su efecto; no rehacer arquitectura o diseño sin motivo. Aprobar solo después de verificar el resultado. Entonces considerar la etapa siguiente.

No modificar datos astronómicos para mejorar una imagen; no ocultar ausencias de cobertura; no quitar funciones existentes ni añadir dependencias innecesarias. No crear commits, pushes ni desplegar sin autorización. En cada entrega informar cambios, pruebas, evidencia, límites y estado Git.
